## 邮件发送功能实现计划

### 现状分析

当前邮件功能只有 IMAP 收信（读取、搜索、标记已读），**发送功能未实现**——Compose 按钮只显示占位对话框。Reply/Forward 按钮也是空操作。

关键发现：
- `easy_mail` 包已包含 SMTP 客户端（`SmtpClient`、`MimeMessageBuilder`、`PlainAuthenticator`），无需新增依赖
- `MailAccount` 模型已有 SMTP 配置字段（smtpHost、smtpPort、smtpUseSsl）
- `NexusRichTextEditor` 富文本编辑器已存在（基于 flutter_quill），可直接复用
- flutter_quill 11.x **没有** Delta→HTML 转换器，需要自己写一个轻量转换器

### 实现步骤

#### 1. SMTP 发送层（data/client/）

新建 4 个文件，遵循现有 `MailClient` 的平台条件导入模式：

- **`mail_sender.dart`** — 抽象接口 `MailSender`，定义 `send({required List<String> to, List<String> cc, required String subject, required String htmlBody, String? textBody})` 方法
- **`mail_sender_io.dart`** — 原生实现，使用 `easy_mail` 的 `SmtpClient` + `PlainAuthenticator` + `MimeMessageBuilder`。每次发送建立新连接（connect → authenticate → send → quit），避免连接管理复杂性
- **`mail_sender_stub.dart`** — Web 平台 stub，抛出 "Web 平台暂不支持发送邮件"
- **`mail_sender_factory.dart`** — 条件导入工厂函数 `createMailSenderImpl(MailAccount)`

#### 2. Quill Delta → HTML 转换器（utils/）

- **`lib/utils/quill_delta_to_html.dart`** — 自定义轻量转换器，遍历 Quill Delta JSON 操作序列，生成 HTML 字符串。支持的格式：粗体、斜体、下划线、链接、无序/有序列表、图片、标题、换行段。覆盖 `NexusRichTextEditor` 工具栏暴露的所有格式。

#### 3. 邮件撰写对话框（presentation/pages/）

- **`lib/presentation/pages/mail_compose_dialog.dart`** — 撰写邮件的大尺寸对话框（约 900×640，响应式适配屏幕），包含：
  - **From**：只读，显示当前账户邮箱
  - **To**：收件人输入框（逗号分隔多收件人）
  - **Cc/Bcc**：可展开显示，默认隐藏
  - **Subject**：主题输入框
  - **正文**：`NexusRichTextEditor` 富文本编辑器
  - **底部按钮**：发送（带 loading 状态）、取消
  - 支持通过构造参数预填充（用于 Reply/Forward 场景）

#### 4. Repository 层更新

- **`lib/data/repositories/mail_repository.dart`** — 新增 `MailSender` 实例和 `sendMail()` 方法，委托给 `MailSender`

#### 5. State 层更新

- **`lib/presentation/states/mail_state.dart`** — 新增：
  - `isSending` signal、`sendError` signal
  - `sendMail()` 方法，调用 repository 发送邮件，发送成功后刷新当前文件夹

#### 6. 页面接线

- **`lib/presentation/pages/mail_page.dart`** — 
  - 替换 `_showComposeDialog` 占位方法，改为打开真正的 `MailComposeDialog`
  - Reply 按钮：预填充收件人（原发件人）、主题（Re: 原主题）、正文（引用原邮件）
  - Forward 按钮：预填充主题（Fwd: 原主题）、正文（引用原邮件）

### 不涉及的范围
- 草稿保存（DRAFTS 文件夹操作）
- 附件上传发送
- Web 平台 SMTP 发送（stub 抛出不支持）
- 后端 API（nexus_hub_api）不改动，邮件全程客户端处理
